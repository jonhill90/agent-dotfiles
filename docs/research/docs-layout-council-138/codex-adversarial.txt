codex
The five-way split is the wrong default because it encodes provenance-by-accident as architecture.

`docs/{architecture,decisions,product,runbooks,reference}` looks tidy, but it is not a decision model. It is a filing cabinet. The categories overlap exactly where these repos need clarity: design specs contain decisions, product docs shape architecture, runbooks embed operational architecture, and reference docs often become stale rationale dumps. That means placement becomes subjective, and subjective placement is where documentation starts rotting.

For the fifth repo itself, the strongest argument against the split is its origin: it accreted while an agent produced files one at a time. That is not evidence of a durable information architecture. It is evidence of local convenience under incremental pressure. Importing it would canonize an artifact before proving that readers can find, update, and retire documents correctly.

It is especially wrong for `agent-dotfiles`. That repo has only 12 docs, but several are dense, high-value source-of-truth documents. Splitting them into five buckets would create false distinctions:

- `SPEC.md` could be architecture, reference, or decisions.
- `hierarchy-naming-57.md` is research plus application plus decision.
- `supervisor-disposition.md` is comparative analysis, not cleanly a decision or reference.
- `handoff.md` is living state, not a runbook.
- `provenance-manifest.md` is not merely a decision doc; it is a source-trust ledger.

The current flat layout is imperfect, but the proposed split would make it worse by scattering a small corpus across broad nouns. The better move is to classify by document lifecycle and reader task: canonical docs, current operating state, analysis/research, and historical/audit material.

For `agent-evals`, importing five directories for one file would be absurd. `evals.md` is the repo’s central contract. Burying it under `architecture/` or `reference/` would make the structure louder than the content. Keep it simple until there is actual pressure.

A better convention: use directories only when they separate different maintenance behavior. Living source-of-truth docs should be easy to find; dated analysis should be isolated so it does not masquerade as current policy.

Concrete alternative:

```text
agent-dotfiles/

```
