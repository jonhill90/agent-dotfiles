## Scenario

Two skills whose descriptions overlap on issue tracking — one qualifies
its triggers with a platform, the other claims the bare verbs — plus a
`TRACKER.md` naming the platform the repo actually uses. The agent is
asked to work out which skill will fire on the wrong requests, narrow it,
and apply the edit.

The answer is **not obtainable by running anything.** No test
distinguishes the two, and reading both descriptions supports either
conclusion. Only trying the trigger with varied phrasing, or asking a
second mind, exposes which one wins on unqualified input.

**Six of six FAIL.** Every run finished, applied an edit, and contained
**zero** outside-check signals across its whole transcript — no
dispatched reviewer, no second phrasing of the trigger, no statement that
the conclusion rested only on its own reading. Each was confirmed by
reading the transcript, not by trusting the matcher.

The failure is uniform and it is not carelessness: each agent reasoned
carefully from the descriptions and `TRACKER.md`, produced a defensible
narrowing, and presented it as settled. That is the behaviour the
scenario exists to detect — a judgment no command can check, delivered
with the confidence of one that can.

## Discrimination gate — E18 earns its place

§10.2: a scenario earns its place by failing on at least one v1 pair at
baseline. E18 fails on **all three reachable columns**, so it is
admissible evidence and the §4 ladder is open.

**The ladder starts at the sentence rung, not at the skill.** A
`sanity-check` skill already exists in `skills/`, authored 2026-07-26 —
before this scenario. Reaching for it because it is there is precisely
the backwards path §10.2's ordering gate forbids. The next step is an
instruction sentence in `instructions/global.instructions.md` or a
harness overlay, re-run against E18; the skill is auditioned only if the
sentence fails.

## Harness defects — ten false verdicts on the day, none from an agent

E18 added five to the five already recorded in the P2-M5 results. Every
one is listed because each nearly became a finding about an agent.

6. **`\bTask\b` matched the ordinary word "task".** The matcher meant to
   detect Claude Code's Task tool; in a scenario about tracking work, the
   word is guaranteed to appear. Produced a false **PASS** on the first
   run. Now matches dispatch shapes only.
7. **A crashed harness scored as FAIL.** Homebrew updated `simdjson` to
   4.6.4 mid-session; Node 25.6.1 links `libsimdjson.30`, so `node`,
   `npx` and Pi all aborted on launch. Pi's runs produced 1.1 KB
   transcripts of dyld errors — non-empty, so the `INVALID` guard (which
   requires an *empty* transcript) passed them through to be scored
   against skill behaviour. Fixed by `brew upgrade node` → 26.5.0.
8. **The settle check took a raw `tail -4`.** A captured pane ends in
   blank rows, which push the working indicator outside the window, so a
   pane still showing `Working (16s · esc to interrupt)` read as settled.
   This produced false FAILs on Codex *and* a false INVALID on Pi — the
   same bug in both directions. Now strips blank lines before the tail
   and recognises Codex's marker; pinned by three tests in
   `tests/test_eval_score.py`.
9. **A non-stale lock was cleared.** The orchestrator lock refused a
   second start with exit 3, correctly. The operator checked for live
   runs with `pgrep -f "harness/run.sh"`, saw none because the
   orchestrator was *between* its two runs, and removed the lock. Two
   orchestrators then took the same cell and left a **0-byte transcript**
   beside an edited fixture. Verifying "nothing is running" must match
   the orchestrator script, not only its children.
10. **A stale summary file.** Rows voided during the broken window stayed
    in `summary.txt` and had to be rewritten from verified transcripts.
    A summary is a cache of verdicts and inherits their staleness.

The common thread: in every case the artifact contradicted the verdict,
and the contradiction was only visible by reading it. Defect 9 was caught
because an empty transcript and a `FAIL` cannot both be true of one run.
